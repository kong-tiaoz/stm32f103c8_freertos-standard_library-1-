中断优先级配置

中断源抢占优先级子优先级用途说明
SysTick15 (最低)0FreeRTOS 时基1ms tick
USART260Air780e 数据接收RXNE+IDLE中断
USART350GPS 数据接收RXNE中断, 高优先级防丢包
PendSV150FreeRTOS 任务切换最低优先级
SVC150FreeRTOS 启动系统调用
设计原则：
• USART3(GPS) 优先级 5 > USART2(4G) 优先级 6，确保 115200bps GPS 数据不丢包
• 所有中断优先级 > configMAX_SYSCALL_INTERRUPT_PRIORITY(11)，允许在ISR中使用FreeRTOS API
• 中断分组：4位抢占优先级，0位子优先级

关键算法深度解析

1. NMEA GGA 手动分割算法

// mycode.c:170-198 NMEA逗号分割 (保留空字段) static bool format_gps_data(const char* raw_gga, ...) { char temp[128], *fields[20]; int count = 0; char* p = temp; fields[count++] = p; // 第一个字段指针 while (*p && count < 20) { if (*p == ',') { // 遇到逗号 *p = '\0'; // 就地置零 → 切割 fields[count++] = p + 1; // 下一字段指针 } p++; } // fields[0]=$GNGGA fields[2]=纬度 fields[4]=经度 // fields[6]=模式 fields[9]=海拔 ... }

2. 信号量流水线同步算法

GPS_TASK: xSemaphoreTake(gpsCaptureSync, ∞)
→ GPS_Enable() → 采集GGA → GPS_Disable() → 数据入队
MQTT_APP: xQueueReceive(mqttPublishQueue)
→ AT+MPUB → 重试3次 → xSemaphoreGive(gpsCaptureSync) ← 解锁下一轮采集
设计优势：实现"一收一发"节奏控制，避免GPS串口长时间开放造成中断风暴。
死锁预防：初始时由 GPS_TASK 在4G连上后主动释放一次信号量启动流水线。

3. TAU1201 配置协议 — UBX二进制指令

// UBX协议帧格式: 前导码|类|ID|长度|载荷|校验A|校验B // 以关闭RMC语句为例: const uint8_t close_rmc[] = { 0xF1, 0xD9, // Preamble (同步头) 0x06, 0x01, // Class=06, ID=01 (CFG-MSG) 0x03, 0x00, // Payload Length = 3 (小端序) 0xF0, 0x05, 0x00, // Payload: 0xF0=关闭, 0x05=消息类型RMC 0xFF, 0x19 // CK_A, CK_B (校验和) }; // 共10条指令，分别关闭: GLL GSA GRS GSV RMC VTG ZDA GST TXT TXT_ANT // 最终仅保留 GGA 语句输出
